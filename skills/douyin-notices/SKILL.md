## 输入判断

- 只想知道有多少未读 → 步骤 1
- 想看具体通知内容 → 步骤 2
- 想看某条通知的完整内容 → 步骤 3
- 想删掉某条通知 → 步骤 4
- 想看某条通知的点赞用户 → 步骤 5

## 通知分组（`notice_group`）

| 值 | 含义 |
|---|---|
| `700` | 全部（默认） |
| `401` | 新增粉丝 |
| `601` | @我的 |
| `2` | 评论 |
| `3` | 点赞 |
| `520` | 弹幕 |

## 执行流程

### 1. 未读数

调用 `get_notice_count`（无参数）。返回各分区未读：评论/@、赞和收藏、新增关注等。用于快速回答"有没有新消息"。

### 2. 通知列表

- 单页：`get_notices`（`notice_group` 分组，`count` 每页默认 10）
- 全部：`get_all_notices`（`notice_group` 分组，`limit` 最多条数默认 20，自动翻页）

展示每条通知：类型、来源用户（昵称 + `sec_uid`）、内容摘要、时间，以及 **`notice_id_str`**（查看详情/删除时要用）。

### 3. 单条详情

调用 `get_notice_detail`（`notice_id_str` 必填，来自步骤 2 的结果）。

### 4. 删除通知

调用 `delete_notice`（`notice_id_str` 必填，`action_type` 默认 0）——⚠️ 删除不可恢复，执行前必须确认。

### 5. 某条通知下的点赞用户

调用 `get_notice_digg_list`（`notice_id` 必填 —— 取列表结果里的 `nid_str`；该接口参数名固定为 `notice_id`，与列表接口的 `notice_id_str` 不同）。

注意：服务端现阶段对多数通知返回 `digg_list: null` / `user_list: []`，如实告知用户"服务端未返回点赞人"，不要编造。

## 约束

- 查询类只读，可直接执行；`delete_notice` 需确认
- `notice_id_str` 必须来自列表结果，不能编造
- 不要循环删除大量通知（可能触发风控）；如需批量清理，先向用户说明数量并分批

## 失败处理

| 场景 | 处理 |
|---|---|
| 未登录 | 引导使用 douyin-login |
| 未读数为 0 但用户觉得有消息 | 说明可能属于私信（用 `douyin-im` 或 `list_conversations` 查） |
| 通知内容已删除/不可见 | 服务会过滤掉不可见条目，如实说明 |
| 删除失败 | 重新取一次列表拿最新 `notice_id_str` 再试 |
| 频繁请求被限流（409 / 429） | 等待 20–60 秒后重试，避免连续调用 |
